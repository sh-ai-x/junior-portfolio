Flagship · the artifact that backs every claim

dev-harness-kit · v0.3.239

A Claude Code plugin that turns ad-hoc agent sessions into a deterministic build pipeline: bootstrap → plan → build → review → ship. Guardrails are hooks (code, not model judgment), the pipeline is a state machine, and every completion claim must quote an exit code (Iron Law L3).

Plugin marketplace distribution with cross-runtime hooks

v0.3.239 · 41 skills · 22 hooks · MIT

Ships as a Claude Code plugin (`.claude-plugin/plugin.json`), with a parallel Codex distribution. Hooks run on Claude Code's event matrix (PreToolUse / PostToolUse / UserPromptSubmit / SessionStart / Stop) and on Codex's equivalent lifecycle. The same iron-laws SSOT is consulted by both.

P

Problem

  • AI coding agents ship code without test discipline or commit hygiene. They "claim done" without proof.
  • Plugins today are soft prompts — the model can choose to ignore them. There's no enforcement layer.
  • Claude Code and Codex have similar but incompatible plugin models; users have to pick.
S

Solution

  • Hooks as a code-level enforcement layer: worktree-guard.sh denies Edit/Write in main checkout (must-fail-closed on jq missing).
  • State machine stages: bootstrap → plan → build → review → ship. Each has its own active hooks.
  • Iron Laws SSOT (iron-laws/index.md): 8 immutable rules — L1 requires verification artifact, L3 requires quoted exit code on completion.
  • Runtime adapter layer: lib/runtime_adapters/ so the same hooks fire under Claude Code or Codex.
R

Result

  • ~24,000 LoC source (Python + shell) across hooks/, skills/, lib/, bin/.
  • ~40,000 LoC tests in 118 test files — the model is forbidden by hook from declaring done without these running green.
  • Shipped to v0.3.239 via automated semantic-release workflow (version-bump.yml).
  • Cross-runtime: same hooks enforce the same rules in Claude Code and Codex.

Iron Laws · the rules the model is forbidden to violate

Eight invariants. Enforced by hooks, not prompts.

iron-laws/index.md is the MUST-8 source of truth. The body just lists them — the enforcement lives in the hooks, the state machine, and the test gates.

L1 — Verification artifact
No prod code without test/contract/domain/scenario/feature per methodology.
L2 — Reproduce first
No fix without reproducing the bug (Phase 1 = reproduce).
L3 — Quoted evidence
No completion claim without quoted exit code / test count / build log.
L4 — No placeholders
No TODO / FIXME / "we'll extend later" / "this is a starting point".
L5 — One answer
No option/alternative list when not asked. One answer.
L6 — Skill alpha
New skills must declare alpha: state | enforcement | analysis in frontmatter.
L7 — alpha = enforcement
A skill's alpha lives in parts the model can't self-impose.
L8 — Trim prose
Skill prompt prose that duplicates state-machine/hook/gate behavior must be trimmed.
Stack — and the why

I list tools only when I can defend the trade-off.

Python
Default for the harness core. lib/ is mostly Python because hook output is JSON-shaped and Python's stdlib (`json`, `subprocess`, `pathlib`) is the cheapest match. Avoided for hot paths where I'd otherwise reach for C/Rust.
Bash
For PreToolUse hooks. The shell has to invoke jq anyway, so writing the hook itself in shell keeps the exit-code contract obvious. Python is used when the hook needs more than string manipulation.
jq
Required runtime dependency. Worktree-guard and stop-verify parse Claude Code's JSON hook input via jq. Both hooks fail closed when jq is missing — the design choice is "refuse to run" rather than "best-effort degrade".
GitHub Actions
For CI shape. Four workflows (review / security / ship / version-bump) — each one purpose. The version-bump workflow reads .claude-plugin/plugin.json:version at runtime, so a version bump requires zero constant churn.
pytest
For the 118 test files. Standard Python testing; the harness's stop-verify hook validates against pytest exit codes, not model judgment.
Markdown / Mermaid
For documentation-as-product. Iron laws, rules, and proposals are all MD. Mermaid for diagrams because it's plain-text diffable.
