6dev-kit 워크플로우로 빌드하기

이 포트폴리오를 dev-kit으로 만들 때 쓰는 스킬 조합. 모두 검증된 공식 스킬.

  1. 레포 부트스트랩/dev-kit:bootstrap — CLAUDE.md·active-hooks.json 생성. 첫 진입 가이드.
  2. CI 셋업/dev-kit:ci-setup — PR 검증·테스트·auto-fix 워크플로우. "CI가 초록이면 머지 가능" 상태 보장.
  3. 기능 단위 빌드 (TDD)/dev-kit:build 또는 /dev-kit:build-tdd — Red-Green-Refactor. tdd-guard hook이 production code 전 failing test 강제.
  4. 코드 리뷰/dev-kit:review [paths] — 병렬 multi-dim 리뷰 (correctness·security·architecture). PR 머지 전 게이트.
  5. 린트 / 시크릿 검사/dev-kit:inspect — 8차원 health audit. 죽은 코드·중복·시크릿 노출 사전 차단.
  6. 문서 유지/dev-kit:docs-maintenance — README를 항상 audit. "문서가 코드보다 먼저 stale" 문제 해결.
  7. 버전 / 릴리즈/dev-kit:bump 또는 /dev-kit:ship — 명시적 버전 상승 + 태그. PR-verify 후 ship.
  8. PR 자동 핸즈오프/dev-kit:babysit-pr — CI 빨강/리뷰 변경 시 자동 진단·수정·푸시·재반복.
이 조합이 중요한 이유. 26개사가 공통으로 보는 시그널 중 "왜 이 기술을 골랐는가" + "실배포" + "코드 리뷰 내성"은 dev-kit의 TDD + review + babysit-pr로 자연스럽게 만들어집니다. CI 통과 + 리뷰 통과 = 그 자체가 behavioral 스토리의 근거가 됩니다.

78주 실행 타임라인 (현실적)

막연한 "포트폴리오 만들어야지" → 주 단위 체크포인트로 쪼갬.

Week 1. 부트스트랩 + CI. 레포 골격·README 템플릿·CS 노트 폴더.
Week 2–3. 실배포 프로젝트 1개 완성 (Next.js 또는 Spring, Vercel/Railway 배포).
Week 4. 트러블슈팅 포스트모템 블로그 글 1개 + 기술 선택 비교 글 1개.
Week 5. AI 사이드 프로젝트 1개 (LLM API 활용). 실사용 시 가산점.
Week 6. OSS 컨트리뷰트 시작 — 작은 PR 1개 머지 목표.
Week 7. behavioral.md 5개 스토리 작성 + 모의 면접.
Week 8. 전체 README 재구성 + 최종 리뷰 + CI 통과.
주의. 8주 안에 모든 항목을 100%로 못 채워도 됩니다. 1개의 깊이 있는 실배포 프로젝트 + 1개의 깊이 있는 블로그 글이 10개의 토이 프로젝트보다 강력합니다 (Meta·토스·Vercel 명시).
